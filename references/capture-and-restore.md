# 按需 FrameAnalysis 抓取与恢复

## 先制定最小抓取计划

先看现有 INI、作者缓冲、DDS、日志与用户已有抓取。只有缺少能改变修复判断的证据才补抓。写配置前明确：待验证假设、缺少的数据、目标形态/场景、部件与绘制阶段、必要插槽/缓冲、可能的导出量，以及如何恢复配置。

| 问题 | 优先利用已有数据 | 需要补抓时选择 |
| --- | --- | --- |
| 半透明、异常发光、效果图绑定 | 作者规则、DDS 描述/通道、已有目标 draw 日志 | 目标部件替换前及真正绘制前的少数纹理/描述；仅必要的 CB |
| 模型空洞或缺少裙内身体 | 作者 VB/IB、子部件索引范围、原始模型 | 只有绘制/变形仍不清楚时，抓对应 IB、必要 VB 或骨骼数据 |
| shader/参数执行问题 | 当前 shader 代码和执行日志 | 已选定 shader 与相关 CB；只有需要看代码时才启用导出 |
| 半边脸不动、表情或形变不跟随 | 作者形变数据、控制表、当前核心计算逻辑 | 实际相关计算批次的日志、控制与必要输入/输出；按 [表情与形变](expression-and-deformation.md) 选择 |
| 原 Mod 改造（已授权）：走跑穿模、裙摆伸缩、深色鼓包 | 作者拓扑/权重、已有动作数据、实际绘制与裙层关系 | 仅在明确授权改造后按 [动画与裙层](animation-and-layering.md) 选择动作骨骼/必要最终输入；只有像素来源决定方案时加目标基础颜色或最终画面 |

**不得将全场景 `dump_rt`、`dump_tex`、`dump_cb`、`dump_vb`、`dump_ib` 和全部 shader/HLSL 导出设为默认组合。** 不默认抓全插槽或全角色。先选目标部件、少量资源和一次必要的帧；资源缺少时逐项补齐缺口，而不是直接扩大到全部。

查看实际纹理尺寸/mip、单资源体积、目标重复绘制数量、磁盘剩余空间和可用内存，评估抓取负担。没有通用“绝对安全”的大小或次数阈值；最小抓取降低负担但不保证游戏绝不崩溃。目录里 deduped 硬链接的逻辑字节总量不等于真实占用或可释放空间。

## 核对核心与备份配置

确认正在使用的 `d3dx.ini` 和启动器配置；游戏启动或 XXMI 可能重写设置。按已安装核心的注释、日志和适用文档确认 hunting、analyse_frame、analyse_options 与 shader 导出方式，不能把旧版或其他电脑的数字值直接套用。

修改目标 Mod 原文件前，按 [备份、安装与回滚](workflow-and-handoff.md) 在其同目录创建带实际备份时间的 `.BAK`。`d3dx.ini` 与启动器配置不使用此命名及同目录要求；修改前在工作目录保存可恢复的原始字节、SHA-256，以及本次修改的字段值、诊断调用和段名，写回恢复前也保留当前状态。启动器各版本 JSON 结构可能不同；区分启动器开关与最终生成的 INI，不假定 hunting 的各处值应相同。只使用当前版本已经支持的选项，不猜一个配置键或 shader 缓存命名规则。

下面仅示范目标纹理的描述抓取和插入位置；部件 3、t7 按实际问题替换。描述与执行日志够用时，不另导出贴图或参数缓冲：

```ini
; 在目标Mod本次资源替换之前插入。
run = CommandListWWMIRepairBefore3
; 此处保留作者原有资源替换、材质与效果调用。
; 在发生异常的真正drawindexed之前插入。
run = CommandListWWMIRepairPreDraw3

[CommandListWWMIRepairBefore3]
dump = desc mono ps-t7

[CommandListWWMIRepairPreDraw3]
dump = desc mono ps-t7
```

只有需要判断像素通道时才在所需阶段追加该目标的 `dump = dds mono ps-t7`；需要具体参数或计算数据时才选择对应 CB/资源与阶段。不要把可选贴图、CB、模型和 shader 输出打成默认组合，也不因缺少某一类输出就认定本次描述抓取无效。

只加入读取诊断，不能为抓取修改 `this`、直接绑定、模型或效果参数。使用本次唯一前缀，避免与原段冲突。多个自定义绘制需找真正的异常 draw，不能把诊断随意放在整段末尾。Before 是目标 Mod 替换前，可能已继承其他覆盖的资源；不能仅凭命名叫它“完全原生”。

如果已安装核心支持 `analyse_options = mono` 配合显式 dump，可使用该最小方案；这是需验证的配置示例，不表示已经抓到所有资源。只需要描述时先不要导出 DDS；只需要纹理时不导出全部模型缓冲。需要 shader 代码时选择实际目标及最小支持的导出方式，并在取证后恢复。

## 触发与判断加载状态

由用户操作游戏，配置按当前核心设置单次触发键；使用 F8 时轻按一次，不长按、不连续触发。选择能看到异常的稳定画面，变身时确保目标形态仍在持续。普通/变身或界面/大世界只抓本次真正需要的场景，不能把未捕获场景标记为已验证。

说明是否先切走角色并 F10 重载，或需要完整退出后从加载器启动。新缓冲、启动器重写或反复重载无变化时检查是否加载了正确配置；必要时完整重启。文件写入成功、时间戳变化、一次重启后结果改变都不能单独证明根因。

已授权的原 Mod 动画改造需要多个姿态时，优先保存已确认计算路径的有限连续动作数据，记录帧序、姿势和容量；不连续触发全量 FrameAnalysis 来代替动作序列。此改造取证不作为常规材质修复的默认要求。用户截不到图时，可按当前任务需要抓最终画面或目标基础颜色，仍由用户说明抓取时实际看到的异常，不把“抓好了”自动等同于成功复现。

如果日志没有诊断调用，核对当前启用 Mod、实际调用位置、过滤条件和配置重写，不能立刻加大抓取。未知 hash 的诊断不要设置会排除它的 hash/filter_index 门槛；旧表情校验或另一形态的材质门槛也可能排除目标，仍应通过已确认的部件/计算路径限制作用域。

日志检索要考虑大小写、Unicode 路径截短与资源继承。可用本次唯一 ASCII 诊断前缀，结合完整标记、API 原生调用的缓冲/索引范围、实际阶段和描述交叉定位；不要把原生调用计数与作者自定义绘制混为同一个绘制范围。命令文本没搜到，不单独证明覆盖未执行；替换资源的描述文件名没有 hash，也不单独证明资源缺失。找不到纹理 hash 时保留其描述、上下文和可确认的资源身份，不猜一个原生 hash。

## 游戏崩溃或抓取不完整

1. 停止继续触发，先恢复本次临时抓取设置，保留已有目录与日志。
2. 检查崩溃前是否已经留下目标诊断、作者自定义 draw、shader、资源描述、纹理或 CB。日志尾部没有 Present 不等于所有证据无效；有 Present 也不证明目标资源齐全。
3. 已有证据够用就继续离线分析，不要求补抓。确实缺少时列出缺口，移除不相关部件/阶段/资源和导出，只补最小集合。
4. 同类定向抓取仍反复崩溃时停止试抓，分析触发与配置支持情况，再提出有证据的替代方案；不能以连续重试或更大的全量导出推进。

## 保存、恢复与手动清理提醒

保存与修复结论有关的日志片段、对应完整日志或可追溯位置、选中 DDS/描述/CB/shader、映射及 SHA-256。不要只留下没有来源的结论。原始抓取保留，不将复制关键文件当成删除许可。

移除本次唯一前缀的诊断调用和附加段，核对作者渲染规则恢复。文件期间未变时可恢复确切原字节；期间发生其他变化时仅撤回本次诊断。全局 INI 和启动器 JSON 同样只恢复本次修改字段，保留新设置，并检查下次启动是否会再次生成抓取配置。

启动器可能自行更新无关元数据，JSON 整文件 SHA 变化不证明本次诊断字段被覆盖。核对目标字段、诊断段和本次差异；不要为匹配旧整文件哈希恢复无关设置。

**此技能不自动删除抓取，不生成或运行 FrameAnalysis 删除脚本。** 即使历史交接曾记录自动清理授权，收尾仍改为提醒用户自行处理。也不清理 ShaderCache、ShaderFixes 或未属于本次的效果资源。恢复诊断设置与删除原始抓取是不同操作。

向用户列出本次实际分析的完整抓取目录，并提醒：“抓取文件已保留。确认修复正常且不再需要排查后，请自行删除这些目录；建议保留原始 Mod、修复备份和关键证据。”尚需复核时说明先保留。不要发送整棵 WWMI 目录、通配所有 FrameAnalysis 的自动清理命令，不能把推算的逻辑大小当作已释放空间。

最后记录配置恢复情况、进程是否已重载、每个抓取目录的 `retained` 状态与已发送的手动清理提醒。恢复文件不代表正在运行的游戏已自动加载恢复后的配置。
