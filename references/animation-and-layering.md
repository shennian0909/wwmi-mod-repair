# 原 Mod 改造：动画穿模、裙摆伸缩与服装内部穿插

**仅在用户明确要求或授权修改原 Mod 的模型/动画时使用本参考。** 这里处理的是对原模型固有走跑穿模、中央裙摆伸缩、布面鼓包的改善，属于改造，不是常规兼容性修复。

游戏或资源包变化造成原有绑定、蒙皮或计算失效时，先恢复作者既有资源与行为；不能仅凭“穿模”症状就套用本参考新增碰撞约束。发现原模型本有的缺陷且尚未授权改造时，只记录证据和可选方案，不制作或安装模型修改。

已授权改造时，记录用户要求、目标部位、动作和允许改变的范围，再使用下列方法。第二版仍未解决时，先执行 [失败后的联网研究](retry-and-research.md)。

## 先确认真正穿出的表面

保留用户对动作、位置、左右侧、默认/切换服装和外观的描述。区分露腿、裙边露出、深色布面遮到浅色布面，以及阴影或材质异常；“黑色鼓包”不能直接记成膝盖穿模。

将作者索引范围、实际 draw、替换资源和最终可见部件对应起来。一份 draw 或一个连通网格仍可能包含外裙、衬里、翻面和多层布面；不能只检查两个 Component 之间的距离。必要时用已抓相机、最终顶点输入、纹理/UV 和基础颜色还原异常像素的来源。基础颜色里已出现深色面时，先检查材质来源与遮挡顺序；不要未经证据把问题归因于运动模糊或时序重建。

用户无法提供截图时，可以根据待解问题选择最终画面、目标基础颜色/法线与必要顶点输入；无需强求截图。离线投影和作者贴图预览要标为候选分析，不能冒充修复后的游戏截图。

## 建立可以重放的动画数据

核对作者 Position、Blend、Vector、UV、Index 的格式、步长、编号范围与打包语义；检查原始/修复权重归一化、接缝和重复位置。物理计算中合并一致的位置组时，保留用于 UV、法线或材质分界的渲染顶点及其属性。

确认蒙皮矩阵、根变换、坐标空间、计算输入/输出顺序以及顶点 shader 的后续位移。实际绘制可能还有材质或轮廓偏移，不能只用简化蒙皮结果代表最终表面。缓冲名字包含 Native/Before 不证明来源原生；用抓取阶段、资源描述和 SHA 核对。

## 选择改动并分散变形

优先保留作者原有拓扑、裙长、腰部锚点、UV、贴图和已认可的外观。权重过渡可在合理邻域中平滑，但不能把裙子整体锁到某一条腿。切开中央、删面、加不透明遮挡或明显交叠会改变外观；用户已拒绝时撤回，并在后续记录该约束。

只有固定模型修整时，说明它对其他姿势的边界。已有实际动画数据且能够限定计算路径时，可考虑局部位置约束、邻接支撑及身体/布面分离。将修正分散到与作者拓扑相符的邻域，结合锚定、边长或活动范围限制中央伸缩；“分散”不能变成不断把整裙向外扩张。位移界限依据本模型的间隙、尺度和失效姿势决定，不把用户的相对形容直接当作厘米测量。

除身体与裙面的避让外，必要时保留同一服装内部的作者前后层次。静态重心坐标不一定还包含变形后的接触点；检查当前姿势的投影是否落在目标面内，没有真实重叠的配对应跳过。将碰撞、平滑及裙层排序作为联合检查，后续平滑若再次破坏避让或层次就重新验证，而不是假定最后一遍处理必然安全。

只查顶点会漏掉面中部被膝盖穿过的情况；按证据增加三角形内部采样或面与身体的检查。快速动作还要考虑相邻姿态间漏检，而非只检查动作结束的一帧。

## 计算资源与安装配置

新增计算前核对实际 HLSL 声明、typed/structured 格式、容量、步长和 SRV/UAV 标志。绑定范围覆盖真正使用的最高槽位，不能让重放工具沿用旧上限而漏绑新增资源。避免同一资源同时作为输入和可写输出；按计算阶段解除冲突绑定。

检查状态保存/恢复、每个分支的退出路径与 QA/QB 等缓冲交替顺序。计算可写输出需要用于普通顶点输入时，按当前框架语义复制到兼容的顶点缓冲，并回读核对。法线/切线修订保留打包标志，UV 中可能包含额外渲染数据，不为修裙任意重写。

需要重放时先用当前已加载修订建立可比基线，再检查新约束、缓冲复制和安装 INI 的实际调度顺序。可用独立参考核对计算结果；确认 shader 编译通过不等于 INI 正确绑定或游戏已加载。

## 连续动作与游戏验证

按本次异常检查相关左右腿、换步、抬膝和相邻过渡；有已保存的连续动作数据就复用，只补缺少且会改变判断的姿势。分别检查身体穿出、裙层反转、面内覆盖、中央伸缩、白/浅色外裙完整性和静止形态。不要为通过一个姿态降低整段动作的验证要求，也不把此案例的帧数、坐标轴、迭代数或半径设为通用常量。

离线检查报告写明覆盖的动作与阈值。包含缓冲回读、复制或诊断的时间不代表实际游戏帧率；新增计算的性能影响按需要在正常游戏状态评估。用户反馈“没有改善”时，查当前修订是否真正执行，并复核异常表面的身份，不能只据离线通过继续加大参数。

最终按默认/实际使用裙装的原异常动作请求游戏确认。保留“用户视觉确认”和“修复后 GPU 抓取确认”两种证据的区别；未复抓不影响记录明确的用户通过结果，但不能虚构绑定确认。收尾恢复临时配置、保留抓取并提醒手动清理。

## 方法来源及适用边界

以下原始资料在 2026-10-14 查阅，仅解释方法和接口语义；后续使用时仍按当时版本重新核对。

- [Position Based Dynamics，作者论文](https://matthias-research.github.io/pages/publications/posBasedDyn.pdf)：以位置约束处理形变与碰撞，可用于研究局部支撑和避让的设计；不直接证明 WWMI 中某份补丁有效。
- [NVIDIA PhysX 3.4 Cloth 归档手册](https://nvidiagameworks.github.io/PhysX/3.4/PhysXGuide/Manual/Cloth.html)：介绍身体碰撞、自碰撞、虚拟采样点、伸缩约束和快速运动的连续碰撞；此旧模块已弃用，参考其思路，不假定鸣潮 Mod 可以调用这些 API。
- [3Dmigoto Resource Copying](https://github.com/bo3b/3Dmigoto/wiki/Resource-Copying)：参考资源复制与引用语义，具体实现核对当前安装的框架版本。
- [Microsoft CSSetShaderResources](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-cssetshaderresources)：核对槽位范围以及输入/输出冲突导致输入置空的行为，避免漏绑后把零结果误判为算法无效。
