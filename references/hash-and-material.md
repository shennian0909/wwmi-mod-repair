# hash、材质与模型判定

## 建立可核对的映射

每条结论至少关联：当前资源包/版本、形态与场景、draw/IB/部件、PS 或相关 shader、抓取阶段、插槽、实际资源描述与 DDS 内容、作者资源和执行规则。文件名中的纹理 hash、原始 hash、资源指针、shader hash 与模型 IB hash 不是同一概念，不能混用。

对照目标 Mod 替换前与真正 `drawindexed` 前的绑定。前一个绘制可能已替换资源，后一个绘制会继承；标为 Before/Native 的抓取不一定是游戏未修改的原生资源，必须看调用顺序。作者自定义 DrawIndexed 与游戏原生 draw 分开记录。共享 atlas、相同 hash 或同槽位不保证同一部件和条件分支使用同一资源。

检查两类故障：覆盖规则缺少当前 hash；覆盖规则已有该 hash，但资源选择、条件或执行阶段错误。仅搜索“新 hash 是否存在”会漏掉后者。对现有错误规则，找同份 Mod 的作者原始规则和实际资源，不能另加一个同 hash 冲突规则。

## 条件、检测时机与材质作用域

当前 hash 和作者资源都正确而画面仍错时，检查条件实际何时成立。追踪 `$mod_enabled`、角色检测标志及换装/技能变量的赋值、Present 或其他阶段的复位，以及目标部件触发覆盖时的状态。旧包可能只在头发设置检测；服装先绘制就会跳过新增材质规则。变量名称按当前包核对，不把某一检测变量视为所有 Mod 的固定接口。

不足以判断时，在目标部件的覆盖触发前读取条件：按原有条件分支执行不同的只读诊断标记，结合真正绘制前的少量描述判断。不能为抓取强制修改检测变量，或把诊断也放进那个可能不成立的材质条件，使失败分支再次漏抓。

根因确认后，可在该角色已匹配的缓冲与索引范围中修正必要的检测时机，或在自身部件的材质触发期间设置局部作用域并及时复位。选择符合当前作者结构的最小改动，核对每条退出路径；不能简单删除保护条件、把别名改成永久生效或盲目给所有部件加检测。

身体专用 atlas、控制图和脸部可能共享 hash，却使用不同 UV 或尺寸。需要限制身体图时将其作用域限定在实际身体覆盖触发内，避免图传入脸部或其他组件。批量迁移另查命名空间和 Master/技能变量是否确实声明，不能复制一个未定义引用。

## 纹理内容与通道

`Texture31`、`ResourceTexture35` 等编号以及 `CLEAR`、`EFFECT` 文件名仅用于定位，不能当作固定语义。先查 DDS 尺寸、格式、mip、色彩空间和通道内容；必要时再解码选中的贴图，避免一次解码全部大纹理。

Alpha 不总是透明度，B/Alpha 可能控制变身附加层、流光或材质效果。近白、全白、全零与有图案的控制图可能产生不同结果；不能把“看起来都是白图”视为等价。二进制 SHA 不同也不一定意味着像素内容不同，要按当前 shader 的实际采样用途判断。

每份 Mod 使用自己的作者资源；同角色不同 Mod 的资源编号、尺寸、通道和内容可能不同。使用一份已成功 Mod 的判断方法，不能直接复制它的 DDS、资源名称或映射表。

头发颜色与光照应按作者发型/发色分支配对。生成光照图的运行时 hash 可能变化或与其他部件共享；确有当前绘制证据时，可在独立颜色材质触发的相同分支配对自身作者光照，而不是给共享生成 hash 添加全局替换。主贴图正确仍需检查实际附加层，不能用主图替换成功推断全部控制图已正确。

`ps-t7 = null` 等直接绑定可能是作者主动关闭某层效果；要查注释、条件、原始规则和实际表现，不能把所有 null 当成资源丢失。也不能为半透明问题统一添加 `ps-t9` / `ps-t10`、关闭剔除、提高自发光或修改公共 shader；这些可能引入额外材质层和整块发光。

资源包 HD/其他变体、shader 替换和 RabbitFX 只在实际相关时进入判断。日志出现 dump 或 ShaderRegex 名称不能证明它改变了颜色；检查赋值、插入代码与真正的执行顺序。

## 材质与几何分界

轮廓与几何正常而特定形态异常时，优先查材质绑定。普通与变身都在相同位置空缺时，检查作者资源是否有对应顶点、索引和绘制范围。贴图再完整也不能显示不存在的面。

裙内身体补全要尊重作者骨骼、UV、法线和部件划分，检查连接处、姿态变化、穿模与额外材质层。不能用全局剔除关闭替代实际缺面；对几何试验单独备份、标记并限制作用域。用户选择旧版视觉结果时按其要求恢复。

表情只动一侧或特定动作下变形异常时，按 [表情与形变](expression-and-deformation.md) 核对计算及骨骼路径，不能仅凭“半边脸异常”判定缺贴图或缺面。

## 一对一缺失纹理别名的暂存工具

`scripts/stage_texture_aliases.py` 用于**已确认缺少、没有冲突的纹理 hash 别名**，克隆指定 Mod 的完整作者规则并保留原字节。它不安装补丁，不修改游戏文件，也不会验证证据引用是否真的支持映射；调用者必须完成证据检查。

映射 JSON 示例，使用实际源 SHA-256、已存在段名与保存证据：

```json
{
  "expected_source_sha256": "源INI的64位SHA-256",
  "aliases": [
    {
      "source_section": "TextureOverrideAuthorEffect",
      "new_hash": "0123abcd",
      "new_section": "TextureOverrideCaptured_0123abcd",
      "evidence": [
        {
          "reference": "保存的日志或映射报告路径",
          "draw": 123,
          "component": "实际部件",
          "slot": "ps-t7",
          "form": "实际形态",
          "scene": "实际场景"
        }
      ]
    }
  ]
}
```

这里的 hash、draw 和插槽是格式示例。暂存目录必须是新目录，且在目标 Mod 的 INI 目录及 Mod 加载树之外。工具检查源哈希、段名唯一性、条件闭合、源规则类型、既有同 hash 配方冲突和字面资源文件，生成暂存源快照 `original.ini`、`patched.ini`、差异、映射与报告。安装补丁前仍须按 [备份、安装与回滚](workflow-and-handoff.md) 在待修改原文件旁创建带实际备份时间的 `.BAK`。已存在且完整等价的别名不重复追加。

遇到下列情况需要人工核对后制作有明确作用域的补丁：已存在但绑定错误的规则、共享/动态材质、直接插槽绑定、几何覆盖、UTF-16、作者原有重复段或未使用的缺失声明。不能为了让工具通过而删除作者原有内容、放宽冲突检查或将这些情况强行当作新别名。

安装前按所选模式检查完整差异：兼容性修复保留作者有效分支与旧 hash，每项改动依据明确，无新增冲突与缺失资源。纯材质兼容性修复检查几何和按键指纹未变；必要资源适配或已授权材质/变体改造按记录的范围核对变化，保留未涉及的作者行为。已有历史疑点记录为基线，不能冒称全部文件原本没有问题。
