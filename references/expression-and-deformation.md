# 表情与形变诊断

用于半边脸冻结、左右表情不同步、特定动作下脸部或眼嘴变形异常。先区分作者缺面、骨骼/位置问题与表情计算问题；不要仅凭脸部异常就改贴图或重做一侧模型。

## 检查作者数据与当前执行

先确认静态脸部是否完整，作者顶点和形变数据是否覆盖两侧，有无无效编号、越界、非有限值或接缝。检查骨骼/位置绑定和作者表情设置、加载命令。随后核对实际安装核心的计算逻辑、资源布局和单位，不能借用另一版本的算法或 checksum。

核对当前相关计算调用是否为单批或多批，各批的匹配条件、校验、条目起点/数量、控制表和作者数据是否一致。旧单批识别未匹配新多批调用时，可能出现原生控制边界与作者条目混用；这是一种需要执行证据的原因，不是所有半脸问题的默认结论。

## 只补必要的计算证据

| 要确认的问题 | 优先数据 |
| --- | --- |
| 哪些批次实际执行、条件是否匹配 | 目标计算调用日志、必要的参数或控制表 |
| 批次是否使用正确条目范围 | 控制表、起点、数量与缓冲容量 |
| 编号及变形如何对应作者数据 | 必要的顶点编号、位移及相关基础位置 |
| 最终位置或骨骼是否另有异常 | 选定阶段的必要输入/输出或骨骼数据 |

先利用已有作者缓冲、日志和核心代码。确实需要补抓时按 [抓取与恢复](capture-and-restore.md) 选择目标计算与少量资源；不导出全场景贴图、全部模型或全部 shader。未知批次不要用旧校验门槛排除，仍按已确认的计算/角色路径限制范围。

记录资源被修改的顺序与抓取阶段。脸部 IB、位置或其他数据可能已经继承作者替换；名称叫 Native/Before 不证明它是原生数据，先核对来源及 SHA。只有通道映射需要时补对应原生控制、编号和基础位置，不能把作者 IB 当作原生编号依据。

## 适配与验证

保留作者原始缓冲；修订资源另行命名、备份并限定在已确认的计算分支。核对各批控制边界、条目数、顶点编号、倍率与容量；未知其他布局不能强行套用已观察到的批次。

通道编号相同不保证动作相同。需要映射时依据实际控制数据、空间形变及匹配可信度，保留可靠对应的作者动作。无法可靠对应的通道不盲目复制或拼接；如依据原生残差适配，限定已证实的脸/眼范围，说明推导方法、可信度与未验证通道，避免将身体动作注入服装。

新增的零值或覆盖缓冲应明确初始化，按实际核心要求在必要的调用中清空，避免未初始化参数影响表情。检查相关资源恢复和各分支退出路径，保持无关材质、绘制、骨骼与按键行为。

当计算语义仍不清楚或需确认根因时，可依据当前核心算法离线重放选定输入，比较实际控制和最终位置；记录误差、容量、编号与有限值。重放复现或缓冲回读通过是离线证据，不能宣称所有表情已在游戏验证。

新增或替换缓冲后说明是否需要完整退出游戏并从加载器重启。合并检查原异常场景的左右脸、眼睛和嘴部；只有确实受影响的形态或动作才扩展检查。用户确认该场景正常就记录该范围，未知批次与没有单独测试的通道仍保留边界。

收尾撤下本次计算诊断并恢复临时字段，保留原始抓取及关键证据，提醒用户自行删除不再需要的明确目录。接续以最新修订和安装 SHA 为准，避免重跑旧设置脚本覆盖已经验证的结果。
