# 工作流、批量范围与交接

## 核对当前安装

路径从用户指定位置或实际安装配置读取，以 `WWMI_ROOT`、`MOD_PATH`、`WORK_DIR`、`CAPTURE_PATH` 表示任务变量，不预设盘符、用户名或资源包目录。确认正在使用的加载器根目录；同名配置副本不能作为当前运行配置的证明。

核对实际 WWMI/XXMI 和相关资源包、RabbitFX 等组件版本及 Mod 作者要求。只有当前问题确实涉及某个组件才继续检查它。版本更新后，旧映射需重新核对；用户询问最新版本或更新回归时查相应官方资料，不能依赖历史版本号。

目录名含 `.zip` / `.rar` 不说明它是压缩文件。真压缩包先列出内容，检查并暂存到 Mod 加载目录之外，避免把原包和解包后的 Mod 同时启用。资源包兼容性与作者要求要按当前安装判断；不要为适配一个 Mod 擅自切换全部角色的资源包。

`DISABLED_` 等名称只反映管理器的一种禁用约定，还要核对实际加载规则与日志。用户切换 Mod 后目录可能重命名；记录确认结果或安装补丁前重新定位，用作者信息、管理器 ID、相对文件树和哈希确认唯一身份，不能继续写过期路径。

## 先查齐，再集中修改

一次修改到位依赖完整诊断。修改前整理一份足以决定补丁的证据表：异常现象、部位、形态/场景、draw/IB、shader、阶段、插槽、实际绑定、作者资源及预期行为。检查同一材质在上下半身或不同绘制中是否重复出错，检查继承绑定和条件分支；将所有确认的必要修正放入同一补丁。

按入口的两种工作模式记录任务。恢复作者原有外观、动画或功能使用 `task_mode = compatibility_repair`，包括原有变体切换和计算路径的兼容性适配；按用户明确要求改变模型、材质或功能使用 `task_mode = modification`，记录授权依据、改造目标与允许改变的范围。两类改动和验证分别汇总，按实际依赖安排工作；常规修复失败不自动扩大授权，也不强制改造先完成一整轮常规修复。

常规模式默认保持作者资源文件原样。必须补回作者资源或适配资源文件才能恢复原功能时，在 `resource_file_adaptations` 中记录文件、必要性、来源、范围与预期恢复行为；用户明确禁止写入时遵守其限制。修改了资源文件不自动归为改造，只改 INI 也可能是在新增功能。

第二版仍未解决时，在第三版设计与制作前执行 [失败后的联网研究](retry-and-research.md)。记录同一问题的实际修订次数、前两次反馈、查询词、来源和第三版采用这些知识的理由；回滚或新对话不清零历史。部分改善仍属于问题未解决。

证据缺少时先明确“还缺什么、拿到后能决定什么”，一次安排必要的定向诊断；不要把用户反复重载当成排查替代品。一个候选修改无效时复核假设与加载状态。若证据仍不足，承认尚未定位，不能为了完成一次修改而同时改多个无关渲染机制。

多个场景或形态都异常时，先列必要的“场景 × 形态 × 部件”证据表，再选择代表性绘制。下面是可按实际问题删减的示例，不是要求全部抓取：

| 场景/形态 | 部件 | 实际配置与路径 | 绘制、插槽及证据状态 |
| --- | --- | --- | --- |
| 角色界面/普通 | 身体或衣服 | 当前界面配置、部件匹配 | 已有日志/描述、仍缺的数据 |
| 大世界/普通 | 皮肤与衣服 | 当前大世界配置，各自匹配 | 主图与必要附加层是否实际替换 |
| 大世界/变身 | 受影响部件 | 变身配置及分支 | 主材质、附加控制图、触发条件 |

界面可能有不同的身体缓冲或配置，皮肤与衣服可能有不同绘制，变身主图正确仍可能漏掉附加图。不能把一个格子的成功扩展到另一格。已由实际资源和执行证据证明等价的路径可复用已有数据；发型、发色、技能分支只按异常及实际使用范围加入，不默认抓遍所有组合。

当普通与变身形态都有缺口，先确定视角与位置。查顶点、索引、子部件范围与实际绘制：作者已有面而当前不显示时，检查绘制、绑定或计算的兼容性；作者本来省略的隐藏身体面不能通过改材质恢复。新增身体面属于原 Mod 改造，需要用户明确要求或授权，不能从常规修复自动进入。已授权补全时另验证骨骼、连接处、姿态和裙内空间；静态不穿模不代表动画中也不穿模。

## 备份、安装与回滚

本节的同目录时间戳备份要求仅用于 Mod 修复时待修改的 Mod 原文件，包括 Mod 配置与确需修改的作者资源。每次写回这些文件前，在其所在目录创建当前字节的备份，命名为 `原文件名 YYYY-MM-DD HH-mm-ss.BAK`。保留完整原文件名（含原扩展名），使用用户本地的实际备份时间；例如修改 `MOD_PATH\mod.ini` 时，备份为 `MOD_PATH\mod.ini 2026-10-14 16-38-09.BAK`。同秒重名时换用新的实际时间戳，禁止覆盖已有备份。核对备份与写前源文件的 SHA-256 一致后再写入；交接记录保存源文件路径、同目录备份完整路径、备份时间及哈希。agent 工作目录中的副本不能替代这份同目录备份。

Mod 修复中对这些原文件安装补丁、追加或撤回诊断、回滚版本时，均遵循上述要求。该命名与存放要求不适用于 `d3dx.ini`、启动器 JSON、报告、脚本或其他任务，不作为全局备份规范。对全局诊断配置，在工作目录保存可恢复副本、SHA-256 以及本次修改的字段和插入段，恢复时保留期间发生的其他设置变化。补丁、差异、报告及暂存源快照仍置于 Mod 加载目录之外。保留 BOM、CRLF/CRCRLF、Unicode 路径、作者按键、条件分支与其他原有行为。

将原有重复段、未使用的缺失资源声明或其他历史问题与本次引入的错误区分开。纹理别名工具会严格拒绝部分这类输入；这意味着需要人工核对和范围明确的补丁，不意味着应该顺带重写整个 Mod。对纯材质兼容性修复，核对几何与按键指纹未变；对必要资源适配或已授权改造，逐项记录允许改变的文件、绘制、材质或功能，检查未涉及的指纹保持不变。

安装前检查源哈希与准备时一致，路径身份仍相同。只写已经检查的补丁，写后核对字节、资源与作用域。源文件已变时重新分析，不能强覆盖。失败或新增明显回归时还原本次改动；期间有其他修改时使用本次差异回滚，不能覆盖别人的新设置。

用户明确喜欢上一版时恢复其指定版，即使新版离线检查通过。记录仍然存在的局限，不能把用户选择改写成新版游戏验证成功。

## 批量与安装日期

先确认角色/目录、截止日期是否含当天，以及哪些 Mod 是排除项。已有明确回答时沿用，不重复询问。检查是只读范围；批量修改依据当前授权执行，用户已经授权时不反复请求相同许可。

安装日期优先使用实际管理器的 `DateAdded` 等元数据，检查日期格式和年份。文件修改时间可能是解压、复制或补丁时间，不能直接当作安装日期。元数据缺失或含糊的条目单独列为待确认，不静默纳入批量。

Mod 数量按管理器条目或实际包的唯一身份统计，INI 数量另计。先验证试验 Mod，再对其余目标逐份核对相同根因与自身作者资源；不能把一份成功资源直接复制给其他 Mod。保持原启用状态，游戏验证时只启用用户选择的目标，避免同角色多份重叠干扰。

分开记录审计数、实际修复数与修复范围内的游戏确认数。未发现同类证据而保持原样的条目标为未修改/未验证，不能把已修复子集通过写成全部审计条目通过。迁移不仅核对纹理，也核对各包检测赋值时机、条件分支及命名空间引用。

## 验证与交接记录

验证请求说明补丁已安装的位置、需要的重载/重启，以及应检查的形态、场景与部位。一次完整补丁尽量合并相关检查；有多个 Mod 时记录各份结果，用户只测试了一部分就只确认那部分。配置/缓冲缓存或启动器重写可能需要完整退出游戏后重新启动；不能仅凭修改时间判断进程加载状态。

用户对明确列出的 Mod 集合答复“这些都正常”时，可将该集合的整体结果写入对应条目，无需重复逐份追问。保存验证问题中的集合和用户原话；未给出的逐场景、选项或技能明细仍标为未单独列明。答复仅涉及部分、集合不明确或仍有异常时，只确认有依据的条目。

推荐报告字段如下；路径、日期和哈希均填当前实际值，不沿用案例值：

```json
{
  "mod_identity": {},
  "current_path": "",
  "environment": {},
  "scope": {},
  "task_mode": "compatibility_repair",
  "modification_authorization": null,
  "resource_file_adaptations": [],
  "revision": "",
  "backups": [{"file": "", "backup": "", "backup_time": "", "sha256": ""}],
  "changes": [{"file": "", "before_sha256": "", "after_sha256": "", "reason": ""}],
  "evidence": [{"capture_phase": "pre_fix", "reference": ""}],
  "installed": false,
  "file_validation_passed": false,
  "capture_bindings_confirmed": false,
  "game_verified": false,
  "tested_scope": [],
  "user_feedback_verbatim": "",
  "feedback_mod_ids": [],
  "per_scene_results_supplied": false,
  "diagnostic_configuration_restored": false,
  "captures": [{"path": "", "retained": true}],
  "manual_cleanup_reminder_sent": false,
  "unresolved": [],
  "rollback": {}
}
```

`file_validation_passed` 只表示对应文件检查通过；没有复抓就不能把 `capture_bindings_confirmed` 写成真。`game_verified` 只适用于明确记录的已测试范围，批量报告要逐项记录。用户反馈“似乎好了”记录为暂未复现，保留原话，不能升级成全部正常。

给证据标明修复前或修复后；修复前抓取证实条件跳过，不等于修复后的绑定已确认。跟进修订后同步当前补丁引用、安装 SHA、已确认/待确认数量和下一步，保留历史版本及其反馈。接续前核对旧暂存、安装和记录脚本的源 SHA 门槛与写回内容，避免覆盖新补丁或重置已确认状态；只有与当前修订一致且不会覆盖新变化时才复用。

已授权改造中用户拒绝或认可的外观及功能也写入交接：例如不接受中央切缝、认可闭合裙形及平滑过渡，或要求保留指定键位；具体要求和改造方法只适用于所授权的目标，不默认迁移到其他 Mod。更新当前结果时同步旧报告中的“最新修订”引用与待验证状态，但保留各历史版本的失败反馈。文件校验、离线/GPU 重放、修复后抓取和用户游戏反馈分别标记，避免用一个含糊的“已加载”字段合并它们。

交接写明可恢复的备份、当前补丁、未完成项目和下一步所需证据。交接文件由本次任务保存或用户提供，通用技能包不附个人绝对路径、原始抓取、历史报告或账户信息。交接记录也不授权删除抓取。
