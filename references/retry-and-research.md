# 第二版失败后的联网研究

用于同一 Mod、同一异常连续修订仍未解决的情况。此要求也适用于第二版只有部分改善、用户明确反馈“没有变化”，或原问题消失但新增回归尚未解决。

研究遵守当前任务范围：常规兼容性修复围绕恢复作者原有外观、动画与功能；原 Mod 改造按用户明确授权的模型、材质或功能目标研究。检索到新方法不等于获得改变原 Mod 的授权，复杂的兼容性问题也不自动归为改造。

## 何时触发

以已交付给用户验证的实际修订计数，离线候选试验不另算一版。第二次修订尚未达到本次需求，就在制作第三次补丁之前主动联网检索，不等待用户提醒。接续时核对旧记录；改名、回滚、换分支或换对话不能重置同一问题的次数。历史已经超过两次仍未解决时，下一次制作前补做这一步。对另一份 Mod 的新问题单独计数。

取证、只读分析、恢复临时诊断及撤回明显回归可以先完成。新补丁的设计与制作须在检索完成、适用条件与本地证据核对后进行。没有联网能力、检索失败或只拿到无法阅读的摘要时，记录限制并继续独立取证；不能声称已研究，不凭离线记忆直接制作第三版。

## 如何检索和使用

1. 保存前两次的改动、用户原话和已排除假设。列出仍不清楚、且会改变第三版方案的问题；“更大数值是否更好”通常不能替代根因问题。
2. 按症状、处理阶段和技术机制检索；只在确实有关时加入 WWMI、3Dmigoto、D3D11 或已安装版本。常规修复优先检索资源布局、实际绑定与触发顺序、作者原有计算及切换功能的版本适配；已授权改造按实际目标检索材质、功能或模型计算机制，模型/动画目标才需要考虑布料约束、身体碰撞或服装自碰撞。不要只搜 Mod 文件名。
3. 打开并阅读最相关的来源。实现语义优先用当前组件的源码、官方文档；算法优先用原始论文或作者资料。社区经验可帮助形成检索线索，但第三版的技术判断应回到原始来源和本地证据。
4. 每个采用的结论记录网址、查询词、查阅时间、适用版本/前提，以及本地支持或反驳它的资源、draw、阶段或用户反馈。参考资料描述另一引擎的 API 时，仅借鉴方法；先确认 WWMI 实际能修改的阶段，不照搬配置键、资源编号、坐标轴或参数。
5. 写清第三版相对第二版改变了哪个假设、采用了什么知识、为什么符合本 Mod，以及哪些新回归必须检查。若资料未给出能解释现有证据的方案，先补齐取证；不能把搜到文章当作随意尝试的许可。

在任务记录中保存研究依据，技能本身不内置每次搜索得到的旧 hash 或补丁。没有固定搜索条数；是否完成取决于相关问题是否得到可追溯的回答。后续同类失败或症状改变时，更新检索问题与证据，避免继续堆叠已经被反馈否定的方案。

## 研究与第三版的连接记录

至少保存以下信息，可并入 [工作流与交接](workflow-and-handoff.md) 的任务报告：

- `repair_attempt`、前两次用户反馈、仍未解决的现象。
- `task_mode`；涉及原 Mod 改造时另记录用户授权依据与允许改变的范围。
- `research_before_revision`、`research_status`、查询词与查阅时间。
- 来源的 URL、相关结论、适用条件及本 Mod 的对应证据。
- 第三版采用和放弃的方案、变化理由、安装与回退路径。
- 文件检查、修复后抓取绑定确认和实际游戏验证的独立状态。

第三版安装后仍需原异常动作/场景的用户确认。联网研究和论文中的算法正确性不等于当前 Mod 已在游戏中修好。
